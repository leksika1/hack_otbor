# Что поменять к следующей сессии

## Правила в CLAUDE.md / AGENTS.md

- [ ] **Повторяющиеся вызовы Read одного и того же файла** (high, шаги 34, 125) - После первого чтения файла сохранять его содержимое в переменной сессии и при необходимости использовать сохранённые данные вместо повторного вызова Read.
  - Причина: Агент не сохранил или не проверил содержимое файла после первого чтения, вероятно из‑за отсутствия механизма кэширования или привычки перечитывать файл без необходимости.
- [ ] **Обрезка и смещение кадра после рендера** (medium, шаги 154) - Включать обязательную визуальную проверку полученного файла сразу после рендера перед объявлением задачи завершённой.
  - Причина: Агент не выполнил проверку визуального результата после рендера, полагаясь только на внутренние метки завершения, поэтому не заметил дефекты кадрирования и позиционирования.
- [ ] **Попытка чтения несуществующего файла через Read** (medium, шаги 191, 192) - Перед вызовом Read для файла, который должен быть создан предыдущей командой, сначала проверять его существование (например, через ls или test -f) или убедиться, что команда завершена.
  - Причина: Агент не проверил наличие файла перед чтением и предположил, что он уже создан, вероятно из-за неверного порядка выполнения шагов или отсутствия ожидания завершения предыдущей команды.
- [ ] **Неудачное завершение процессов agy из-за сигнала, приводящего к exit code 144** (medium, шаги 263, 264) - Перед завершением процессов сначала уточнить их наличие через pgrep, выполнить kill/pkill с проверкой кода выхода и вывести сообщение об ошибке при неудаче; только после подтверждения завершения переходить к следующему шагу.
  - Причина: Вероятно, агент не убедился, что указанные процессы существуют и что команда kill/pkill успешна; если процессы уже завершились или игнорируют сигнал, kill может вернуть ненулевой код, а оболочка могла быть прервана внешним сигналом, что привело к exit code 144.
